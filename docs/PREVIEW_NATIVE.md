# Отдельная демонстрационная версия на существующем сервере

Контур не заменяет действующий сайт. Эта инструкция дополняет Docker-вариант в `PREVIEW_RUNBOOK.md`: на сервере Debian 10 Docker не установлен, поэтому используется подготовленная Linux standalone-сборка с собственным Node 22.

## Изоляция

- Рабочий каталог: `/srv/labstudio-preview`; исходное `/var/www/constructor.net` не изменяется.
- Отдельный процесс MariaDB из уже установленного бинарника: `labstudio-preview-db.service`, свой пользователь ОС, datadir и socket; порт `127.0.0.1:13307`. Он запускается с `--no-defaults`, не использует конфигурацию или данные production MariaDB на 3306.
- Приложение: `labstudio-preview-web.service`, свой пользователь ОС, Node внутри релиза, порт `127.0.0.1:18080`. Общий Node 14 и существующее приложение на 3000 не обновляются.
- Новый Nginx listener из `ops/nginx/labstudio-preview-port.conf`: `https://labstudio-inc.ru:8443`. Конфигурация существующих 80/443 не заменяется. Используется уже действующий сертификат этого домена, DNS менять не требуется.
- У preview отдельные имена cookie авторизации и собственный `NEXTAUTH_SECRET`: вход/выход не перезаписывает сессию прежнего сайта на том же домене.
- Среда: `PREVIEW_DEPLOYMENT_MODE=isolated-preview`, `PREVIEW_RESTRICT_EXTERNAL_FLOWS=true`, `BILLING_CRON_ENABLED=false`. Реальные платежи, регистрация, сброс пароля, письма и фоновые списания отключены. Production-секреты в среду не передаются.
- Только публичный каталог и синтетические demo/admin-аккаунты. Перенос реальных пользователей в демонстрационный контур не выполняется. Изменения demo не синхронизируются обратно в production.

## Сборка

Из корня репозитория:

```sh
docker build -f frontend/Dockerfile.bundle --target artifact --output type=local,dest=/absolute/private/build .
```

`bundle/` содержит Linux Node, Prisma engine, сервер, `.next/static` и публичные файлы. Секреты и каталог `public/uploads` исключены из контекста. Переносите сборку как новый каталог в `releases/`, не поверх запущенного релиза. Публичные изображения находятся отдельно в `shared/uploads/task` и подключаются ссылкой `public/uploads`.

Конфигурация `/srv/labstudio-preview/preview.env` принадлежит root с правами 0600; systemd передаёт её процессу. В ней задаются собственные `DATABASE_URL`, `NEXTAUTH_SECRET`, публичный `NEXTAUTH_URL`, режим изоляции и `UPLOAD_IMAGE_TASK=/srv/labstudio-preview/shared/uploads/task`. Пароли не сохраняются в Git. Шаблоны systemd находятся в `ops/native/`.

## Данные и обновление

Первичный каталог импортируется allowlist-скриптом `frontend/scripts/import-catalog.ts` в пустую preview-базу. Он проверяет имя и хост БД, идентификаторы, связи и наличие изображений. Дополнительно поддерживается `licenses.json` с публичными тарифами; специальный demo-тариф не заменяет их и не показывается на публичной странице. Пользователи создаются `seed-preview-users.ts` только после явного подтверждения и проверки preview-БД.

Снимок от 07.09.2026: 6 курсов, 296 категорий, 4 964 задания, 4 859 связей категория–задание, 10 руководств, 4 публичных тарифа. Из 1 985 файлов архива публичных изображений 1 486 уникальных файлов используются активными заданиями. Реальные пользователи/подписки/платежи не импортируются; для demo создана отдельная синтетическая подписка.

Перед следующими миграциями сохраните дамп **preview-базы через её собственный socket**, проверьте код завершения и SHA-256. Нельзя использовать обычное `mysql` без явного preview socket/порта: оно подключится к production. Для новой копии каталога используйте пустую отдельную preview-схему, а не очистку действующей.

При обновлении переключайте `current` на подготовленный релиз и перезапускайте только `labstudio-preview-web.service`. Проверяйте `/api/health`, вход и сохранение. Если проверка не прошла, верните предыдущий `current`; миграции БД требуют отдельно проверенной совместимости/резервной копии.

## Проверка

```sh
systemctl status labstudio-preview-db labstudio-preview-web
curl --fail https://labstudio-inc.ru:8443/api/health
curl --fail https://labstudio-inc.ru/ >/dev/null
```

Локальные проверки: `npm test`, `npm run typecheck`, `npm run build`. Для E2E запустите приложение с заполненными preview-переменными и передайте `E2E_BASE_URL`, `PREVIEW_DEMO_EMAIL`, `PREVIEW_DEMO_PASSWORD`, `PREVIEW_ADMIN_EMAIL`, `PREVIEW_ADMIN_PASSWORD` процессу `npx playwright test`. Тест редактирует только синтетический конспект, восстанавливает видимость каталога и удаляет собственный тестовый конспект. Полный редактор телефона не входит в ТЗ; мобильный E2E проверяет публичную страницу и ограничения внешних операций.

## Как отключить только preview

Остановите `labstudio-preview-web.service` и `labstudio-preview-db.service`. Переместите только `/etc/nginx/conf.d/labstudio-preview-port.conf` за пределы `conf.d`, выполните `nginx -t`, затем graceful reload. Не удаляйте базы или релизы, не останавливайте nginx/mariadb и не меняйте действующий virtual host `labstudio-ssl.conf`.

Это демонстрационный запуск, а не переключение основного сайта и не акт приёмки. Окончательное включение реальных аккаунтов, финальный перенос и изменение основного домена выполняются после согласования.
